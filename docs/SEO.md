# Search, answer engines and public discovery

The original public pages are retained. `SITE_URL` supplies the canonical origin for metadata, social cards, structured data, sitemaps and machine-readable references. Changing a hostname does not require editing page source. Static pages, populated `/fastest/{category}` collections, three `/leaderboard/{tier}` collections, public website reports, published articles and explicitly public `/founder/{username}` profiles form the indexable surface. Private founder/account profiles, authentication, the administrator panel and preview utilities remain outside discovery.

## Metadata and identity

`src/lib/seo/metadata.ts` supplies a single title suffix, complete Open Graph/Twitter cards, absolute internal canonicals and explicit robots controls. General and Googlebot-specific follow directives agree. Child pages do not lose social images through Next.js metadata replacement. Blog pagination has a canonical for each actual page; malformed, repeated or out-of-range page numbers render the not-found response instead of cloning the last archive page. Unrecognized query variants remain noindex. Privacy email-preference URLs canonicalize to `/privacy` and use `noindex` plus `no-referrer` so preference tokens are not treated as public content.

The entity graph identifies TheFastestWeb, its publisher and the current operator **Cengiz YILMAZ**, linked to `https://cengizyilmaz.net`. It does not invent historical founding claims, social accounts, addresses, awards or ratings. Public contact comes from `SITE_EMAIL` (the provisional default must be confirmed before public launch). The previous nonfunctional SearchAction was removed because the restored homepage does not implement its advertised query search.

Public content has appropriate WebPage/AboutPage/CollectionPage, ItemList, BreadcrumbList and BlogPosting data. Schema uses actual listed websites and article metadata. Performance scores are not fabricated review ratings. Every JSON-LD script uses `safeJsonLd`, including stored website names and article titles. These fields help describe the visible content; they do not guarantee a special search appearance. [Google structured-data guidance](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data), [organization documentation](https://developers.google.com/search/docs/appearance/structured-data/organization).

## Article and measurement evidence

Explicit frontmatter authors are preserved. Unsigned legacy articles use TheFastestWeb as their editorial publisher, rather than attributing old work to the new operator. Publication dates remain unchanged. Optional `updated` frontmatter is used only for actual editorial changes and supplies the visible update date, article modified metadata and sitemap timestamp. A shared chronology check omits invalid updates and dates before publication from the HTML, Open Graph, JSON-LD, sitemap and Markdown references. Rendering a page never invents a new modification date. [Google article documentation](https://developers.google.com/search/docs/appearance/structured-data/article).

Website reports distinguish recorded mobile lab measurements from real-user Core Web Vitals. Metadata does not promise daily monitoring or instant results independent of provider configuration. A missing test is not described as a measured zero. Collection markup describes the actual entries shown. Founder discovery uses the same explicitly public registry as the profile route; private account IDs, account names and email addresses are never added to the public corpus.

## Crawling and sitemaps

`/sitemap.xml` is the top-level runtime index. It groups child documents by `pages`, `sites`, `blog`, `categories` and `founders`; every `/sitemaps/{section}/{page}.xml` contains **at most 200 canonical URLs**. Page numbers are zero-based. Exactly 200 or 400 entries produce one or two children; 201 produces two. Empty sections have no child link. A nonexistent section/page, zero-padded alias or empty child returns 404, while query variants return 400. The index does not advertise artificial empty pages.

Website rows use stable primary-key order and the same listed/active-or-verified/unarchived predicate in counting, XML and Markdown. Blog/category entries use stable slug order; public founders use the shared canonical username/visibility helper. Offset pages reflect current public data: they are deterministic for a given dataset, not a frozen snapshot across concurrent publication changes. Re-read the index when collecting a fresh snapshot. No private profiles, legacy UUID profile URLs, redirects, removed URLs, assets or Markdown variants are included.

Only actual stored dates are emitted: service-page editorial dates when present, article publication or valid later editorial updates, website measurements or creation, and public-founder updates. Undated collections omit `lastmod`. Sitemap generation/deployment time is never used as a modification date, and the index omits file-modification dates it cannot substantiate. Database/catalog outages return an uncached 503 instead of a misleading empty replacement. XML values are escaped and every URL uses the configured canonical origin. The protocol's 50,000-child index ceiling is checked explicitly instead of silently cutting links. [Sitemaps protocol](https://www.sitemaps.org/protocol.html), [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

Robots advertises the sitemap for a public deployment. Demo mode blocks crawling, emits an empty sitemap index and adds `noindex` response/metadata controls. Do not submit the temporary demo domain to search engines. Canonical URLs and sitemap URLs should agree. [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

Production robots permits crawlers to reach the sign-in page, preview utilities and legacy `/links` route so their existing `noindex` metadata or 404 can be read. These pages remain excluded from sitemaps. Blocking a public URL in robots.txt prevents crawlers from observing its `noindex` directive. API and admin crawl restrictions remain; authorization still protects private data. [Google noindex guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

The hidden outbound badge/link block was removed from the home page. It added network requests without useful visible content. The separately retained legacy `/links` utility remains noindex and outside the sitemap.

## GEO and AEO

The useful foundation is crawlable, accurate content: direct answers, clear headings, visible authorship, dated measurements, meaningful internal links and structured data matching the page. The About page explains who operates the service, what a lab score describes and how paid placements differ from organic results. Public reports and articles provide the sources a reader can inspect.

`/llms.txt` is a concise navigation guide. `/llms-full.txt` contains all published service-page and category prose, article references, and an exhaustive public-corpus manifest. It explicitly distinguishes content in the current file from records in linked parts; it never claims every product is reproduced inline. Complete editorial articles are included inline when the combined file fits 1 MiB, otherwise every whole article remains accessible through the listed article parts.

`/llms/catalog.md` lists every `/llms/sites/{page}.md`, `/llms/founders/{page}.md` and `/llms/articles/{page}.md` part, with record totals and page counts. Parts contain at most 200 records and previous/next links. Article parts also stay under 1 MiB without splitting/truncating articles; the former 128-article cutoff is removed. A single article beyond the supported per-part bound causes a visible 503 rather than a false completeness claim. Website and founder parts select only named public fields. Publisher-supplied descriptions are encoded inside JSON source-data fences, with fence/HTML delimiters escaped, and labeled as source claims rather than service instructions. Missing measurements are not emitted as scored zeroes.

Live corpus/manifest responses use `no-store`, generic 503 with Retry-After on outages, and 404 for missing parts. Query aliases are rejected before database access. Demo exports do not query live site/founder records. Markdown remains `text/markdown`, `nosniff`, and `noindex, follow` on production, so the canonical HTML pages remain search documents; demo responses are `noindex, nofollow`. The index links and public Markdown exports require no authentication and grant no additional database permissions. See the [llms.txt proposal](https://llmstxt.org/).

These files are navigation aids. Google does not require special AI text files or schema for AI Overviews or AI Mode: the canonical page must be indexed and eligible for a search snippet. No ranking, citation or FAQ search appearance is promised. Hidden pricing FAQ markup was removed because it did not match visible questions and answers. [Google AI features guidance](https://developers.google.com/search/docs/appearance/ai-features).

Bing similarly describes crawlability, indexing, clear structure and evidence as the foundation for search and AI grounding; neither rankings nor citations are guaranteed. Citation visibility can be measured after ownership verification in Bing Webmaster Tools. [Bing Webmaster Guidelines](https://www.bing.com/webmasters/help/bing-webmaster-guidelines-30fba23a), [Bing AI Performance](https://www.bing.com/webmasters/help/ai-performance-9f8e7d6c).

## Validation and release steps

Local checks cover configured-origin canonicals, title/social metadata, consistent Googlebot follow directives, demo and private noindex behavior, observable utility noindex controls, actual-date handling, truthful entity data, JSON-LD escaping and sitemap route scope. Blog route regressions check invalid/repeated/out-of-range archive parameters and compare rendered article dates with Open Graph, JSON-LD and Markdown. Dedicated tests cover 200/201/400/401 pagination, all article parts beyond 128, canonical founder privacy, raw publisher-copy serialization, empty/out-of-range children, malformed/query aliases and outage behavior. PostgreSQL fixtures validate 401 distinct site records across 200/200/1 parts and exclude every inactive/private lifecycle. `scripts/verify-seo.mjs` performs read-only checks against a loopback runtime; the production runtime harness also runs it. Browser smoke retains accessibility, page-error and responsive-layout checks separately.

Before public launch:

1. Confirm the permanent domain and contact address; set `SITE_URL`, `AUTH_URL`, `SITE_EMAIL` and production deployment mode together. Update OAuth callbacks, payment returns, email links and public media origins consistently.
2. Configure `SEARCH_CONSOLE_VERIFICATION` and `BING_VERIFICATION`, then verify the domain in the respective accounts. No verification or search-engine submission has been performed by this local change.
3. Inspect representative home, category, tier, website and article URLs on the final public host. Check HTTP status, canonical, robots and rendered structured data using the search engines' inspection tools.
4. Submit the sitemap and observe actual indexing/citation data. If changing domains, implement redirects for genuine retained counterparts and complete the search engines' domain-move workflows.
5. Confirm the public host/CDN allows intended crawlers while authentication and private routes stay protected. Robots directives are not authorization.

IndexNow remains intentionally inactive. `INDEXNOW_KEY` is reserved and performs no submissions. Enabling it later requires a verified final host, ownership-key serving and a bounded submission flow that rechecks public eligibility and never sends private URLs. [Official IndexNow protocol](https://www.indexnow.org/documentation).
