# IndieTools old-host cutover

TheFastestWeb remains the live application until IndieTools has imported and
verified its products, history and articles. The cutover runtime is built into
the same web image, stays disabled by default and reads only the final reviewed
artifact generated by IndieTools. It does not change DNS, import data or infer
destinations.

## Safety contract

The web process opens its port only when all of these checks pass:

- `TFW_REDIRECT_CUTOVER_ENABLED=true` and both manifest settings are present;
- the artifact is a regular, non-symlink file no larger than 8 MiB;
- its name is `thefastestweb-redirects-v1-<first-16-digest>.json`;
- the configured full SHA-256 pin equals the manifest digest;
- the digest recomputed from the canonical JSON contract is identical;
- every route and image mapping is valid, unique and covered by the manifest
  counters;
- no route, badge, award or avatar remains in `review`;
- every destination is on `https://www.indietools.app` and matches an allowed
  canonical URL family.

An invalid activated artifact makes startup fail closed. It never falls back to
the old dynamic application. With the gate false, the manifest is not loaded
and the current application behaves exactly as before.

The production build also validates the single JSON artifact, when present in
`runtime/redirect-manifests`, and fails for an unresolved or invalid release
set. Keeping zero JSON artifacts is valid while the feature remains inactive;
shipping more than one is refused so an operator cannot select a stale file by
mistake.

At request time the consumer performs an exact normalized path lookup. A
single trailing slash is normalized. Encoded, repeated-slash and malformed
paths do not alias a reviewed route. Tracking parameters (`utm_*`, `gclid`,
`dclid`, `fbclid`, `msclkid`, `ref`, `referrer`) are stripped. `page` is
accepted only once, as a positive integer, and only for a path carrying the
manifest's `legacy-pagination-consolidation-v1` policy. The generated V1
manifest applies that policy to `/blog` and reviewed `/fastest/{category}`
families. Other query keys return 410.

Mapped `/api/badge/{slug}` requests use the `legacy-speed-badge-v1` adapter.
The first `theme` and `variant` values win, unknown values become `dark` and
`glow`, and preview, domain and every unrelated parameter are discarded.
Unmapped badge, avatar and award paths return plain-text 410 and can never
render an HTML page. All other unknown paths also return 410 with `noindex`.

`/health/live` and `/health/ready` continue to exercise the retained app.
`/health/redirect-cutover` returns a no-store, bounded JSON response containing
only the manifest identity and counts. Per-request logs contain a hashed rule
key, status class and digest prefix; they never contain a raw URL, query,
cookie, credential or destination and are rate limited.

## Prepare the immutable release

Do this only after the IndieTools production deployment and imports are healthy.

1. Freeze the final TheFastestWeb source revision and a post-migration-0011
   database dump. Record both SHA-256 values in the migration evidence.
2. Regenerate the IndieTools content and redirect artifacts from those exact
   inputs and the final production target snapshot.
3. Complete every editorial and route decision. Regenerate until both
   `coverage.review` and `coverage.badgeReview` are zero.
4. Run the IndieTools HTTP verification matrix. Every redirect destination must
   return the final 200 response directly, with the expected canonical and no
   accidental `noindex`; every image destination must return its declared image
   content type.
5. Copy the generated artifact without editing it into
   `runtime/redirect-manifests/`. Its filename must carry the first 16
   characters of its full digest.
6. Validate the exact file that will enter the image:

   ```powershell
   $manifest = (Resolve-Path '.\runtime\redirect-manifests\thefastestweb-redirects-v1-<prefix>.json').Path
   $digest = '<64 lowercase hexadecimal characters>'
   npm.cmd run redirects:validate -- --manifest $manifest --digest $digest
   ```

   The command prints only the digest and counts and exits nonzero for a stale,
   renamed, modified or unresolved artifact.

7. Build and test the release image. Record the immutable image digest as
   `CUTOVER_IMAGE_DIGEST`. Also record the currently running known-good image
   digest as `PRIOR_IMAGE_DIGEST`; do not rely on a mutable tag for rollback.

The Docker image owns the copied manifest and its directory as `root:root`; the
web process runs as `nextjs` and cannot replace it.

## Stage with the gate off

Configure these values on the **web service only** and deploy the cutover image
with the gate still false:

```dotenv
TFW_REDIRECT_CUTOVER_ENABLED=false
TFW_REDIRECT_MANIFEST_PATH=/app/runtime/redirect-manifests/thefastestweb-redirects-v1-<prefix>.json
TFW_REDIRECT_MANIFEST_DIGEST=<full digest>
```

Verify `/health/live`, `/health/ready`, login-independent public pages and the
current application logs. The worker and scheduler do not receive these
settings. Stop new legacy scheduling and payment entry points through their
existing controls only after the corresponding IndieTools features are live;
retain the database, storage and backup chain for rollback.

## Activate and verify

Activation is one controlled web-service environment change:

```dotenv
TFW_REDIRECT_CUTOVER_ENABLED=true
```

Recreate the web container from `CUTOVER_IMAGE_DIGEST`. Startup must emit one
`redirect_cutover.ready` event with the expected digest prefix and counts.
Then verify with redirect following disabled:

```powershell
curl.exe -sS -D - -o NUL https://thefastestweb.site/health/redirect-cutover
curl.exe -sS -D - -o NUL https://thefastestweb.site/site/<reviewed-slug>
curl.exe -sS -D - -o NUL "https://thefastestweb.site/fastest/ai?page=2&utm_source=cutover-check"
curl.exe -sS -D - -o NUL "https://thefastestweb.site/api/badge/<reviewed-slug>?theme=light&variant=scorecard&preview=99"
curl.exe -sS -D - -o NUL https://thefastestweb.site/__cutover-unknown-check__
curl.exe -sS -D - -o NUL https://thefastestweb.site/api/badge/__cutover-unknown-check__
```

Expected results are one direct 301 to the exact reviewed IndieTools URL, a
canonical badge URL containing only `theme` and `variant`, and 410 for both
unknown checks. Fetch each destination separately with redirects disabled and
confirm 200, no `Location`, canonical/indexability for HTML, and
`image/svg+xml` for Speed badges. Repeat the automated IndieTools Control Center
verification against the live old host and retain its bounded report.

Do not add a homepage catch-all. Do not activate a manifest merely because a
sample passes; the full manifest matrix must pass.

## Roll back

The fastest rollback is the same single gate:

1. Set `TFW_REDIRECT_CUTOVER_ENABLED=false`.
2. Recreate the web container from the unchanged cutover image.
3. Confirm `/health/live`, `/health/ready` and a normal TheFastestWeb page.
4. If the application image itself is suspect, deploy the recorded
   `PRIOR_IMAGE_DIGEST` exactly. Do not rebuild the prior commit or use a moving
   tag.
5. Resume any paused scheduler/worker only after their database and queue
   compatibility is verified. Do not restore or overwrite production data as
   part of an HTTP rollback.

Keep the manifest, source/database checksums, both image digests, health output,
verification report and rollback timestamps together in the release evidence.
