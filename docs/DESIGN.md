# Product design direction

Reading this as a performance directory and founder community for developers, with a clear, confident product language and real measurement evidence.

The public marketing/editorial surfaces use the design-taste-frontend skill. Product tables, workflows and administration use accessible semantic HTML and purpose-built reusable components in the existing Tailwind4 system. This is a product redesign authorized by the master plan; existing URLs and the speedometer brand asset are preserved.

Design variance5, motion3, density5. Main accent amber, anchored by the existing speedometer logo; neutral cool gray surfaces replace the previous brown palette. Light and dark themes share semantic CSS tokens and follow system preference with a manual override. Display/body use Outfit; measurements use JetBrains Mono. Remove the third downloaded font. Corners:8px controls,12px panels,20px feature surfaces. Elevation only for overlays/popovers. Focus rings, errors and labels remain visible in both themes.

Audit findings: old navigation competes with ten empty advertising tiles; hero is generic and repeats external promotions; public statistics hide errors as zero; long lists filter client-side; legal/about pages still describe the former owner; dense interfaces have inconsistent spacing; infinite decorative animations ignore reduced motion. Preserve functional sidebar advertising, authentic speed/history data, existing public links and verified submission rules.

New composition: compact72px navigation, restrained left-aligned headline, real current competition summary, server-filtered ranked directory, technology/country discovery, recent sites, founders and editorial content. The hero's visual is a working view of actual leaders, with an honest empty state before standardized measurements exist. No generated testimonials, decorative telemetry or fabricated scores. Advertising remains clearly labelled and visually secondary.

Reusable controls cover buttons, fields, tabs, dialogs, drawers, filters, pagination, metrics, charts, skeletons and empty/error states. Forms retain labels, keyboard operation and recoverable errors. Data tables use native table semantics with responsive summaries. Every action must have a real server path and appropriate ownership checks.

Before shipping: inspect desktop/laptop/mobile, both themes, keyboard focus, reduced motion, overflow, empty/error states and disabled providers. Run browser journeys, accessibility checks and a local Lighthouse audit. Existing SEO routes and structured data stay functional throughout.
