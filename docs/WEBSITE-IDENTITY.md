# Website identity and redirects

Submission preparation reads bounded HTML through the pinned-DNS HTTP transport. Every redirect hop is checked against the public-address policy. It checks duplicates again after observing the final transport URL, before purchasing PageSpeed measurements. A declared canonical URL contributes to duplicate identity only when its exact origin matches that observed final URL. Different schemes, www hosts, subdomains and tenant paths are not guessed aliases. A canonical hint from another origin never establishes ownership or authorizes a claim.

HTTP publication requires the authenticated, successful preparation receipt and both unexpired server measurements. The measured source URL is immutable throughout publication. If preparation could not read the site, publishing retries bounded metadata retrieval and fails with a temporary retry response if transport identity still cannot be established. Text fields can still be entered manually.

The transaction locks sorted source/final/canonical identity keys and checks `url`, `normalized_url` and `redirect_url` together. New listings preserve the normalized submitted source in `url`, index the observed canonical/final identity in `normalized_url`, and retain a different final transport address in `redirect_url`. Concurrent aliases cannot consume two sets of proofs or create two listings. Conflicts never return another private listing's name or identifier. Preparation result reads recheck current listing visibility and ownership before returning a claim target.

Imported raw URLs remain byte-for-byte unchanged, including their historical tracking, fragment or casing. When such a URL differs from its normalized source, the source key remains in `normalized_url` and its strongest observed canonical/final alias occupies `redirect_url`. A final transport address with a separate same-origin canonical is checked through the mandatory metadata observation before publication; there is no schema addition or rewrite of historical source URLs.

Mobile background retests observe metadata alongside the existing measurement under a bounded timeout. Only a successful, current, lease-owned measurement may persist identity evidence. An unavailable response, unsafe redirect, lost lease or changed site source cannot rewrite identity, remove history, alter ownership, or change listing lifecycle/visibility. A successful redirect observation is retained as evidence; redirect, parked, suspended and removed lifecycle decisions are separate explicit operations. Screenshot history remains bound to the source URL rather than the canonical duplicate key.
